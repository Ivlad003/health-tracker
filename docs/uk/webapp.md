# 📱 Telegram Web App (Mini App)

[🇬🇧 English version](../en/webapp.md)

Mini App — застосунок на React 19 + TypeScript + Vite у `web/`. Docker-образ збирає його в `web/dist`, FastAPI віддає за адресою `/app/`. Користувач відкриває його командою бота `/app`. JSON API описано в [food-logging.md §6](food-logging.md#6-api-web-app).

## 1. Структура

```
web/
├── index.html              # завантажує telegram-web-app.js з telegram.org
├── eslint.config.js        # typescript-eslint (з перевіркою типів) + react-hooks
├── vite.config.ts          # base /app/, dev-проксі /api → :8000, конфіг vitest
└── src/
    ├── App.tsx             # фази старту/входу, hash-роутер, нижня навігація, BackButton
    ├── api.ts              # обгортка fetch: bearer-сесія, 401 → один повторний вхід, ApiError
    ├── errors.ts           # код помилки → перекладений текст
    ├── i18n.ts             # словники uk/en (однаковість ключів гарантує тип), форматери
    ├── LangContext.tsx     # useT(): { lang, t, err }
    ├── telegram.ts         # тема, haptics, нативне підтвердження, openLink
    ├── hooks/              # useApi (AbortController), useAction (busy/помилка/повідомлення), useBackButton
    ├── components/         # Section, Field (label ↔ input), Switch, Banner, Loading (скелетон), EntryList, NavIcon
    ├── lib/                # чиста логіка: колір балансу, прийом їжі/порція, зменшення фото
    └── pages/              # Dashboard, Food (+ food/*), Activity, History, Profile (+ profile/*), Admin (lazy)
```

## 2. Автентифікація та сесії

1. На старті застосунок викликає `Telegram.WebApp.ready()/expand()` і, якщо збереженої сесії немає, надсилає `initData` на `POST /api/v1/webapp/auth/telegram`.
2. Токен сесії зберігається в `sessionStorage` (очищується при закритті WebView) і надсилається як `Authorization: Bearer`.
3. Будь-яка активність подовжує сесію на сервері (`WEBAPP_SESSION_TTL_SECONDS`, типово 1 год неактивності), але не довше за 12 год загалом (`SESSION_MAX_LIFETIME` в `app/services/webapp_auth.py`).
4. На 401 `api()` входить повторно з тими самими `initData` (один запит на всі паралельні) і повторює запит. Це працює, поки `initData` свіжі (`WEBAPP_AUTH_MAX_AGE_SECONDS`, 5 хв); далі застосунок показує «Сесія завершилась — відкрийте з бота ще раз». Кожен повторний вхід відкликає сесію, яку ті самі `initData` створили раніше, а кількість обмінів обмежена п'ятьма (`INIT_DATA_MAX_USES`, той самий файл).
5. Особа користувача завжди береться з перевіреної серверної сесії. `initDataUnsafe.user` — лише для відображення; `ADMIN_API_TOKEN` ніколи не потрапляє в браузер; вкладку адміна показує `/me.is_admin`, а сервер перевіряє роль на кожному адмін-запиті.

## 3. Завантаження даних і помилки

- `useApi(loader)` скасовує попередній запит при повторному запуску/розмонтуванні (жодних оновлень стану після розмонтування, старі відповіді не перезаписують нові). Завантажувачі — `useCallback`.
- `useAction()` обгортає зміни: одна за раз, кнопки вимкнені під час виконання, помилки ніколи не стають необробленими rejection, haptics на успіх/помилку.
- `api()` перетворює HTML-сторінки помилок (502 від проксі) і мережеві збої на `ApiError` (`server_error`, `network_error`, `bad_response`); `errorMessage()` перекладає коди — сирі коди бекенду не показуються.
- Кожен екран має скелетон під час завантаження і стан помилки з кнопкою **Ще раз**.

## 4. Екрани

| Екран | Що робить |
|---|---|
| Дашборд | Баланс (дефіцит — зелений / у межах цілі — синій / профіцит — помаранчевий / великий профіцит — червоний), прогрес до цілі, плитки їжі й активності (тап → Історія / Активність), швидкий запис, записи за сьогодні |
| Їжа | Прийоми їжі (типовий — за місцевим часом, ті самі межі, що в бота), грами (порожньо = звична порція продукту; введене значення завжди має пріоритет), пошук із затримкою та імпортом FatSecret, «Мої продукти» одним тапом, записи за сьогодні з видаленням, фото (перед надсиланням зменшується до JPEG ≤ 1600 px), чернетки, новий продукт, «Перевірити фразу» |
| Активність | Підключення/показники WHOOP, показники Apple Health з локалізованими одиницями та часом синхронізації |
| Історія | Останні 7 днів одним запитом `GET /food-entries/range`, локалізовані назви днів, розгортання дня |
| Профіль | Окремі картки з власною кнопкою «Зберегти»: ціль калорій (перевірка 500–10 000), особисті дані (вибір часового поясу, нагадування `type="time"`), налаштування запису, інтеграції (відключення з підтвердженням), фрази за замовчуванням (продукт обирається з «Моїх продуктів») |
| Адмін | Прапори можливостей, збої outbox та імпорту історії з повтором (окремий lazy-чанк) |

## 5. Інтеграція з Telegram

- Тема: CSS використовує змінні `--tg-theme-*`, які задає SDK; `<html data-theme>` слідує за `colorScheme` і `themeChanged`; поза Telegram — `prefers-color-scheme`. Кольори заголовка/фону слідують за темою.
- Нативна **BackButton** на всіх екранах, крім Дашборду; **HapticFeedback** на зміни; **showConfirm** для небезпечних дій; `openLink` для OAuth.
- Безпечні зони: `env(safe-area-inset-bottom)`, `--tg-viewport-stable-height`, `--tg-content-safe-area-inset-top`.
- Доступність: кожне поле має `<label for>`, перемикачі — `role="switch"`, банери — `role="alert"/"status"`, прогрес — `role="progressbar"`, кнопки навігації — `aria-current`; цілі дотику ≥ 44 px.

## 6. Віддача та кешування

`app/main.py` додає для `/app/*`: `Content-Security-Policy` (скрипти лише з self і `https://telegram.org`, `frame-ancestors` — self + `*.telegram.org` для Telegram Web), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cache-Control: no-cache` для `index.html` і `public, max-age=31536000, immutable` для `/app/assets/*` з хешем у назві. API отримує `Cache-Control: no-store`. Маршрутизація на hash (`/app/#food`), тож SPA-fallback на сервері не потрібен.

## 7. Розробка

```bash
cd web
npm ci
npm run dev        # http://localhost:5173/app/, /api проксіюється на uvicorn :8000
npm run lint       # eslint (з типами, react-hooks, без «висячих» promise)
npm test           # vitest: API-клієнт, однаковість словників, чиста логіка
npm run build      # tsc (застосунок + конфіг vite) і vite build → web/dist
```

Поза Telegram `initData` немає, тож застосунок показує екран «відкрийте з бота». Для роботи в браузері створіть сесію з підписаними initData (наприклад, `app.services.webapp_auth.sign_init_data` з локальним токеном бота), виконайте в консолі `sessionStorage.setItem("ht_session", "<token>")` і перезавантажте сторінку.

CI (`.github/workflows/apple-health-postgres.yml`, job `webapp`) запускає `npm ci`, `lint`, `test` і `build` на кожен push/PR.

## 8. Ще не реалізовано (дорожня карта дизайну)

`docs/design/` описує цільовий інтерфейс. Ці частини **ще не** зроблені й ведуться як пункти дорожньої карти, а не баги:

- Дашборд: кнопка голосу (голос — через бота), pull-to-refresh, активності в «Останніх».
- Облік їжі: запис голосу в застосунку, вільний текст «Аналізувати» з чекбоксами розпізнаних позицій, живий сканер штрихкодів (шлях сканування — фото; сканер Telegram лише для QR), модалка редагування порції.
- Активність: кнопка синхронізації WHOOP, графік пульсових зон, список/деталі тренувань.
- Історія: періоди День/Тиждень/Місяць/Свій, зведення, графіки, фільтри, пошук, експорт.
- Профіль: аватар/«з нами з», цілі білка/активності, одиниці, експорт/видалення акаунта, «Про застосунок»/довідка.
